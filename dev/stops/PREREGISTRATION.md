# 預先註冊：z 停損與時間停損

寫定日期：2026-08-26。**本檔在跑之前定稿。**

## 問題

`zscore_trading.py:317-320` 有三個停損判準，**現行只用了第一個**：

```python
is_cap_stop  = stop_loss_pct > 0 and (-pnl / capital) >= stop_loss_pct   # 現行 0/5/15%
is_z_stop    = use_dynamic_stop and abs(z) > dynamic_stop_z              # 從未啟用
is_time_stop = max_holding_days > 0 and days_held >= max_holding_days    # 從未啟用
```

## 為何值得測

**其一，文獻用的是 z 停損，不是損益停損。**
Kim & Kim (2019) 的動作空間即「進場門檻 × 停損邊界」，兩者皆以標準差計；
[SAPT](https://pmc.ncbi.nlm.nih.gov/articles/PMC8369334/) 的 SADQN 同樣以標準差設交易與停損邊界。
**本研究的停損以損益百分比計，與該文獻族不可直接比較。**
`dynamic_stop_z` 是使兩者可比的機制，且早已接線。

**其二，時間停損有既有診斷支持。**
`config.py:55-57` 載明「>63d 未收斂配對勝率 26-46%、期末強平桶 ΣPnL 大幅為負」。
2026-08-26 另測得持倉超過 N 天仍未收斂者的**最終** `capture_frac` 單調惡化：

| 門檻 | 仍在倉數 | 最終平均 capture | 最終收斂比例 |
|---:|---:|---:|---:|
| 21 天 | 4,520 | −0.020966 | 44.6% |
| 42 天 | 3,526 | −0.044134 | 31.8% |
| 63 天 | 2,830 | −0.067123 | 20.4% |
| 84 天 | 2,235 | −0.086790 | 12.0% |

## ⚠ 先驗應往下修：既有反面證據

`dev/ml_formation/dyn_exit.py` 的 OHLCV 動態出場測試：
以衝擊觸發平倉，門檻 6/5/4/3/2 的每期淨捕獲為 0.127/0.122/0.091/0.040/0.018，
**基準（不啟用）0.144 最高、單調遞減**——「被砍掉的部位續抱回來的機率高於繼續發散」。

該測試是**衝擊觸發**，與 z 觸發、時間觸發不同，故不能直接外推；
但它與上表的「久未收斂者最終更差」表面矛盾，**兩者必有一個是選擇效應**：
上表是**事後**條件於最終結果，不等於「當下砍掉能拿多少」。
本案即為裁決此矛盾而設。

## 設計

| 項目 | 設定 |
|:---|:---|
| 臂 | `Grid NOGRP-SDP`、`Grid NOGRP-SSD`、`Grid GICS-SSD`、`Grid NOGRP-DTW` |
| 評估格 | **`top_n ≥ 5`**（常規做法；Top1 不列入主判準） |
| z 停損 | `use_dynamic_stop=True`、`dynamic_stop_z ∈ {3.0, 4.0, 5.0}` |
| 時間停損 | `max_holding_days ∈ {21, 42, 63}` |
| 其餘 | 全部沿用基準（`entry_z=2.0`、`stop_loss_pct` 網格不變），單一變因 |
| 形成期 | 借用，不重跑 |

**六個值事前固定，不再擴充。** 兩個機制**分開檢定**，各自 Bonferroni $0.05/3 = 0.0167$。

## 門檻

對各基準臂，以逐日抽樣、三檔停損等權後對 `top_n ∈ {5,10,20}` 等權，
循環 block bootstrap（$L$=126、$B$=10,000）檢定年化報酬差（啟用 − 基準）。

**須為正且 $p < 0.0167$。** 兩個機制中任一過關即記為有效，各自報告。

## 試驗宇宙

`_build_filename` 對兩者皆有後綴（`_DSZ{n}`、`_MHD{n}`），故與既有結果**並存不覆寫**。
兩者為**同一 METHOD 下的配置變體**（如 `entry_z` 變體），
故 method $N$ 維持 53，config $N$ 增加。DSR 主口徑為 method，影響有限——
惟仍須於重跑 `regime_cost_dsr_eval` 後更新 `TRIAL_CENSUS` 的 config 值。

## 已知限制

本案改變的是**出場**，而 `capture_frac` 代理是以「z 穿越 0 或期末」定義的，
無法表達提前停損。**故本案無代理可用，一律實跑回測。**
