## D.1 為何這一項需要預先登記

要證的命題——「自由持倉的動作空間導致過度交易」——正好是最容易事後
合理化的一類：跑完之後，換手率無論高或低都能編出解釋
（高就說「果然過度交易」，低就說「訓練不足所以不敢動」）。
把判準寫在前面，是唯一能讓該結論具有否證性的做法。

另有一個具體理由：**這件事原本有證據，但證據已經不在了。**
`strategies/trading/drl_threshold_trading.py` 的 docstring 記載
「換手率約 6 倍、Sharpe −1.1 ~ −2.3」，但資料庫重建後
FQI／LSTM／DQN 的明細列數為 0（附錄 B）。
本次是**重跑取回**，不是新發現；既然是重跑，就必須先說清楚
「取回到什麼程度算成功」，否則等同於用結果去背書一段既有敘述。

## D.2 假說與判準（執行前寫定）

| 編號 | 假說 | 否證條件 |
| :--- | :--- | :--- |
| **H1（主要）** | 自由持倉（v1/v2/v3）的**換手率**顯著高於門檻選擇（v4）與固定門檻 | 三條臂中達到「比值 ≥ 2.0 且 BH 校正 $p < 0.05$」者少於 2 條 |
| **H2（次要）** | 自由持倉臂的 Sharpe **不高於** v4 | 任一自由持倉臂的 Sharpe 高於 v4 |
| **H3（機制）** | 績效劣勢**主要由換手成本造成** | 零成本重算後 Sharpe 差距縮小未達 50% |

**達標須同時贏過兩個基準**（H1 原文為「高於 v4 與 Z-Score」）。

效果量門檻取 **2.0 倍**而非 docstring 記載的 6 倍：這是重跑取回，
不要求逐位重現，僅要求同方向且幅度非瑣碎。

**明確不主張**：本消融不主張 v4 可交易、不主張任何一臂有正報酬。
此處量的是相對的行為差異，不是績效。

**若 H1 不成立的處置（亦於執行前寫定）**：不改判準、不換視窗、不調參重跑；
處置是把該段證據由「否證證據」降級為「設計沿革」，正式證據改用
`dev/action_learn`。此退路先寫下來，是為了讓「跑出來不如預期」
不至於變成修改判準的動機。

## D.5 估計式

| 項目 | 設定 |
| :--- | :--- |
| 觀測單位 | 配對期（非交易日） |
| 主要結果變數 | 每期進場次數（含反向） |
| 檢定 | 逐期配對差分 ＋ 循環區塊拔靴，$L$ = **6 期**、$B$ = 10,000 |
| 效果量 | 總進場數比值 $\Sigma_{\text{處理}} / \Sigma_{\text{基準}}$ |
| 多重比較 | 主要族 3 臂 × 2 基準 = 6 個比較，BH-FDR |

$L$ = 6 期為一個完整重疊週期（126/21），故 108 期對應 **18 個獨立區塊**
——這是本設計統計檢力的實際上限。

**為何效果量用總數比值而非逐期比值**：實測基準臂有約 3% 的期零進場，
逐期比值會除以零；而剔除那些期恰好剔掉「基準不交易、處理臂在交易」的期，
會系統性低估效果。

## D.6 偏離紀錄

以下為執行過程中的**全部**偏離，依時序排列。

### D.6.2　2026-09-15｜第 1、2、4 項改為以 `result.db` 為準

原口徑讀 per-arm 執行日誌，但日誌是**單次啟動**尺度，而本次跑跨四次啟動：
續傳的期印的是「已完成，跳過（checkpoint）」而非 `Skipping period`，
實測 v1／v2 為 90／70、其餘三臂為 175／0——**照原口徑第 2 項必然誤判**。
三項改為以落庫資料為準（D.4 表），只更嚴、與結果數值無關，
且於任何結果產出之前改定。

### D.6.3　2026-09-18｜閘門第 2、7 項實作錯誤，更正後由 FAIL 轉 PASS

**此點必須揭露。** 分析程式首次執行時，核對第 2、7 項**未通過**。
原因不在回測，而在核對程式把「左緣」實作為**單一期**而非整個區塊——
預先登記第九節的文字是「除**左緣**外無缺期」，而左緣依 4.1 節的定義是
**形成期起點早於價格索引起點的全部期**。

更正後的判定只用價格日曆與形成期日期，**不涉及任何結果**：
左緣 = 形成起點 < 索引起點（2008-07-01），實測恰為 12 期
（2007-07-12 ~ 2008-06-11）。核對證據：

| 臂 | 缺期 | 扣掉左緣後仍缺（＝中段缺期） |
| :--- | ---: | ---: |
| Z-Score／v4／v2／v3 | 1（2007-07-12） | **0** |
| v1 | 12（左緣全部） | **0** |

且 v1 剩下的 108 期恰為連續段。

> **它確實是在看到失敗之後才改的**，故特此揭露。更動只在「執行是否成功」的
> 驗證方式；假說、門檻、估計式、視窗、凍結清單一律未動；
> 更正的依據全部來自早於資料的原文。

### D.6.4　2026-09-18｜進場定義的穩健性（兩種構造、同一結論）

落庫的 `Entries` 是**部位轉換式**（`Prev_Pos ≠ 0` 的方向改變數 ＋
期末仍持倉數）；分析程式用的是**狀態列式**（`ENTER_*` ＋ `REVERSE_*`）。
兩者在 Z-Score、v4、v3 上逐位相同，在 v1／v2 於交集內差 4／6 列（約 0.7%）。

以部位轉換式重跑 H1：比值 2.868–4.095（狀態列式 2.849–4.067），
BH 校正 $p$ 完全相同，達標仍 **3/3**。**結論不因定義而變。**

### D.6.5　2026-09-18｜H2 必須連帶揭露的口徑事實

取五臂共同期（108 期）會丟掉左緣 11 期，而那正是 2008-07 ~ 2009-06 的
危機反彈窗口——兩個基準的獲利幾乎全在其中：

| 臂 | 交集 Sharpe | 各自全期集 | 僅左緣期 |
| :--- | ---: | ---: | ---: |
| Z-Score | −0.009 | 0.418 | **+1.443** |
| v4 | −0.012 | 0.442 | **+1.541** |

H2 的比較在組內是公平的（五臂同一組期），但 v4 在交集上的 Sharpe ≈ 0
**不代表**它全樣本的 +0.442。第四章 4.1.3 節兩者並列。

### D.6.6　H3 的口徑限制

零成本是**用解析成本模型加回摩擦**（淨損益 ＋ friction × 名目額），
**不重新訓練**。政策本來就是在含成本的環境下學到的，
要真正做「無成本世界」的消融得重訓一次，等於再花一次數天的算力。
故 H3 量的是「**同一條政策**在零成本下的績效」，
**不是**「若無成本會學出什麼政策」。

名目額的事件集含 `REVERSE_*`：共用的 `metrics.traded_notional` 原只數
`ENTER%`，會漏掉 v3 的 361 筆反向（占其 534 筆進場的 68%）。
該函式已一併修正（附錄 B.5.8）。

## D.7 無種子控制及其後果

`grep seed` 的結果：`drl_fqi_trading.py`、`drl_lstm_v2_trading.py`、
`drl_threshold_trading.py` **完全沒有**種子設定；
`drl_lstm_trading.py` 只有 gym 的 `reset(seed=None)` 轉呼叫，從未被傳入種子。
故 v1／v2／v3 的每次執行都是一個獨立抽樣。

實測（同一組態各跑兩次）的每期進場次數：

| 臂 | 兩次執行 | 全距 |
| :--- | :--- | ---: |
| Z-Score | 1.57 / 1.57 | **0（確定性）** |
| v4 | 1.57 / 1.57 | **0（確定性）** |
| v1 | 4.33 / 7.33 | 2.2 倍 |
| v2 | 5.79 / 8.71 | 2.0 倍 |
| v3 | 13.07 / 4.71 | 2.8 倍 |

**兩條基準臂逐位確定，雜訊全部在自由持倉那一側。**
預先登記原定「每條自由持倉臂各執行 3 次取中位數」，
實際因算力上限（v1 單臂約 3 天）僅執行 1 次。
**此為與預先登記不符之處，於此記錄**：效果量（2.2–4.1 倍）大於上表的
執行間全距，故結論方向不受影響；但點估計本身帶有未量化的訓練變異，
第五章 5.4 節其一已將此列為限制。
