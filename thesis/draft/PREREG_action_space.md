## 一、為什麼要預先登記

這份消融要證的東西，正好是最容易被事後合理化的那一類：
「自由持倉的動作空間導致過度交易」。跑完之後，換手率無論高或低都能編出解釋
——高就說「果然過度交易」，低就說「訓練不足所以不敢動」。
把判準寫在前面，是唯一能讓這個結論具有否證性的做法。

另有一個具體理由：這件事**原本有證據，但證據已經不在了**。
`strategies/trading/drl_threshold_trading.py` docstring 第 5–8 行記載了
「換手率約 6 倍、Sharpe −1.1 ~ −2.3」，但 `result.db` 重建後
（見記憶 `result-db-size-already-cleaned`）FQI／LSTM／DQN 的明細列數為 0。
本次是**重跑取回**，不是新發現。既然是重跑，就必須先說清楚
「取回到什麼程度算成功」，否則等同於用結果去背書一段既有敘述。

## 二、假說

以下三條在跑之前寫定，方向性、可否證。

| 編號 | 假說 | 否證條件 |
| :--- | :--- | :--- |
| **H1（主要）** | 自由持倉動作空間（v1/v2/v3）的**換手率**顯著高於門檻選擇（v4）與固定門檻（Z-Score） | 三條自由持倉臂中，達到「≥2 倍且 BH 校正 p<0.05」者少於 2 條 |
| **H2（次要）** | 自由持倉臂的 Sharpe **不高於** v4 | 任一自由持倉臂的 Sharpe 高於 v4 |
| **H3（機制）** | 自由持倉臂的績效劣勢**主要由換手成本造成** | 零成本重算後，Sharpe 差距縮小未達 50% |

H3 的用意：把「過度交易」與「因成本而虧損」拆開。
前者是動作空間的性質，後者是它的後果；若只量到後者，這個消融沒有說到動作空間。

> **H3 的口徑限制（必須揭露）**：零成本是**用既有交易明細重算損益**，
> **不重新訓練**。政策本來就是在含成本的環境下學到的，要真正做「無成本世界」
> 的消融得重訓一次，等於再花 6.3 天算力。因此 H3 量的是
> 「**同一條政策**在零成本下的績效」，**不是**「若無成本會學出什麼政策」。
> 這個區別會寫進論文，不以前者冒充後者。

**明確不主張的事**：本消融**不**主張 v4 可交易、**不**主張任何一臂有正報酬。
論文主軸的絕對檢定 6/6 不顯著、DSR 6/6 未過（見附錄），
這裡量的是**相對的行為差異**，不是績效。

## 三、設計

### 3.1 五條臂

| 臂 | 動作空間 | 模組 |
| :--- | :--- | :--- |
| Z-Score | 固定門檻（基準） | `strategies.trading.zscore_trading` |
| DRL v1 | 逐日自由持倉，LSTM-DQN | `archive.trading.drl_lstm_trading` |
| DRL v2 | 逐日自由持倉，LSTM-DQN 修復版 | `archive.trading.drl_lstm_v2_trading` |
| DRL v3 | 逐日自由持倉，FQI | `archive.trading.drl_fqi_trading` |
| DRL v4 | **每期單次門檻選擇** | `strategies.trading.drl_threshold_trading` |

### 3.2 唯一變因

五條臂共用的部分（已實測驗證，非宣稱）：

* **同一批形成期配對**：五條臂的 `formation_strategy_id_base` 全部解析為
  `Grid GICS-SDP`（`formation_pairs` 5,900 列、`formation_progress` 295 期已完成），
  形成期零重跑。
* **同一對沖口徑** `dollar`。v1–v3 未宣告 `SUPPORTS_HEDGE_MODE`，
  依 `run_trading` 的守衛會被誠實記為 `dollar`；為此另建 `dollar` 口徑的
  v4 與 Z-Score 對照臂，而不是沿用主軸那 1,620 列（全為 `signal`）。
* **同一網格格點** Top1 / SL0（`GRID_LOCK`）。SL0 無停損，
  強平事件不被截斷，是觀察「過度交易」最乾淨的一格。

唯一變動的是交易端的動作空間。

### 3.3 為何基底是 GICS-SDP

1. SDP := z(SSD) + z(DTW)（§3.2.4），DTW 佔一半權重，
   且對沖比率與 DTW 臂同樣採雙向 OLS 取 ADF p 較低者。
2. 在 GICS 這一格，15 格等權 Sharpe：SDP 0.076 > DTW 0.068 > SSD 0.043。
3. GICS-SDP 已有現成 v4 臂，且在 §4.2.1 的逐日 HAC + BH 家族中
   BH 校正 p = 0.0278（通過）；GICS-SSD 為 0.0504（不過）。

**不選 GICS-DTW 的理由**：它沒有 v4 臂。新建約 2.6 小時並不貴，
但會讓 §4.2.1 由五個配對底變六個，BH 家族重排。實測敏感度：
新底自身 p ≳ 0.06 時，現有的 GICS-SSD 與 K-means 會被推過 0.05，
顯著數由 3/5 掉到 2/6。事前無從得知新底的 p 落在哪邊，故不動這個家族。

**原本選 GICS-SSD 的理由已撤回**：那個理由是「效果量最大（+0.798pp）」，
而該數字是從 15 格中挑出的最大值——選擇偏誤。

## 四、期間

### 4.1 視窗與期數的關係（2026-09-09 實測，與原先的理解不同）

原本以為 `BACKTEST_START`／`BACKTEST_END` 會篩掉視窗外的形成期。**不是。**
實測（`ABLATION_TAG=PROBE2`）顯示：

1. `run_trading` **一律迭代全部 295 期**；`prepare_backtest_data` 只是把
   **價格索引**裁到視窗，並向前回填 `FORMATION_WINDOW`（252 個交易日）。
   例：`BACKTEST_START=2006-01` → 索引實際起於 **2005-01-03**。
2. 跳過判定只檢查**交易期**日期是否落在索引內；
   **形成期**起點早於索引起點的那些期**不會被跳過，而是丟例外**
   （`Error simulating pair (...): Timestamp(...)`）。
3. 該例外**只發生在 v1**（v2／v3／v4／Z-Score 都能正常跑那幾期）。
   探針中 v1 有 11 期報錯、其餘四臂為 0；落庫時
   **v1 只寫進 15 個配對期，其餘四臂各 26 個**——
   五條臂根本不在同一組期上，這是最直接的證據。
4. **報錯的期照樣被計入，整條臂仍回報 `SUCCESS`。**
   探針中 v1 對 27 期「執行」了 7.4 秒——實際一筆有效模擬都沒有。

第 3 點是設計上的硬約束：若不處置，**v1 的期數會少於其餘四臂**，
五條臂就不在同一組期上，單變因消融的前提破掉。

處置（兩者都在跑之前定死）：

* **視窗左緣多墊 1.5 年**（378 個交易日 = 18 期），讓所有分析期的形成期
  起點都落在索引內；
* 分析階段**取五臂共同期的交集**，並在結果中報出該期數。

### 4.2 選定：`BACKTEST_START=2009-07`、`BACKTEST_END=2018-12`

| :--- | :--- |
| 價格索引實際範圍 | 2008-06-30 ~ 2018-12-31 |
| **五臂共同期數** | **108** |
| 第一期形成起點 | 2008-07-11 |
| 最後一期交易迄 | 2018-12-13 |
| 相對 `split_half` 中點（2013-01-02） | **中點前 54 期／中點後 54 期** |
| **牆鐘估計（單次執行）** | **約 3.3 天**（五臂併組並行，見 4.4） |

### 4.4 成本模型（2026-09-09 無競用實測）

以 `ABLATION_TAG=CLEAN5`／`CLEAN10` 各跑一次、機器上無其他負載，
取兩點斜率外推到 150 episodes：

| 臂 | ep=5 每期 | ep=10 每期 | 每 episode | 150ep 每期 | 108 期 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| v1 LSTM-DQN | 52.5s | 142.7s | 18.03s | **44.5 分** | **3.33 天** |
| v2 修復版 | 30.3s | 96.6s | 13.27s | 32.6 分 | 2.44 天 |
| v3 FQI | 5.2s | 5.3s | （見下） | — | < 1 小時 |
| v4 門檻選擇 | 0.05s | 0.05s | — | — | 數秒 |
| Z-Score | 0.04s | 0.04s | — | — | 數秒 |

**五條臂是循序執行的，不是並行。** `run_trading.py:896` 以「原始策略」為單位
分組，每組即一條臂（網格已鎖成單格），而 `for group_cfgs in groups` 逐組處理；
`max_workers` 只在單一組內生效，對只有一格的組毫無作用。
故牆鐘是**相加**而非取最大：

| 臂 | 單臂 | 累計 |
| :--- | ---: | ---: |
| v1 | 3.33 天 | 3.33 天 |
| v2 | 2.44 天 | 5.77 天 |
| v3 | < 1 小時 | 5.81 天 |
| v4 + Z-Score | 數秒 | **約 5.8 天** |

（上表是**未併組**時的情形，已於下方處置。）

> 起初把它寫成「同時起跑、牆鐘 3.3 天」是錯的。
> 儀表板一次只有一條 `RUNNING`、其餘四條 `PENDING`，即為循序的實證。

**處置（2026-09-10）：改分組鍵，讓五條臂併入同一組。**
`run_trading.py` 的分組處新增一段 env 閘門，僅在 `ACTION_SPACE_ABLATION=1`
時把五條臂併成一組（併入的鍵取 `original_strategies_config` 中真實存在的名字，
否則下方以 `orig["name"]` 反查時整組會被靜默丟掉）。
該組含 v4 故 `is_drl_group` 為真，無 CUDA 時併行度上限 4。

實測：v1／v2／v3 同時 `RUNNING`，v4 於 23.6 秒完成，Z-Score 遞補空位。
**牆鐘回到 `max(v1, v2) ≈ 3.3 天。**

不採「分別起五個行程」：那會讓多個 `run_trading` 同時寫 `result.db`，
是本專案已踩過的競用風險。

| | 循序（原） | 併組（現） |
| :--- | ---: | ---: |
| 牆鐘 | 約 5.8 天 | **約 3.3 天** |

> **四之四那個「83 分／期、6.3 天」的估計偏高約一倍。** 舊估計來自
> 一次有競用的量測（當時另一支 `run_trading` 正在跑），且取的配對不同。
> 無競用重測為 18.03 s/episode，對應 44.5 分／期。

> **v3 的成本不能用同一條斜率外推。** `drl_fqi_trading.py` 第 108 行是
> `self.sweeps = max(50, drl_episodes)`——ep=5 與 ep=10 都被夾到 **50 sweeps**，
> 兩點其實是同一個訓練預算，所以測到的斜率（+0.01 s/episode）是夾擠的假象，
> **不是** FQI 與 episodes 無關的證據。正式跑 `drl_episodes=150` → 150 sweeps，
> 約為實測預算的 3 倍，換算後仍不到 1 小時，不影響牆鐘。

### 4.5 隨機性：四條學習臂都沒有種子控制

`grep seed` 的結果：`drl_fqi_trading.py`、`drl_lstm_v2_trading.py`、
`drl_threshold_trading.py` **完全沒有**種子設定；`drl_lstm_trading.py` 只有
gym 的 `reset(seed=None)` 轉呼叫，從未被傳入種子。
因此 v1／v2／v3 的每次執行都是一個獨立抽樣。

實測（同一組態各跑兩次，`PROBE` 對 `CLEAN`）的每期進場次數：

| 臂 | ep=5 兩次 | ep=10 兩次 | 全距 |
| :--- | :--- | :--- | ---: |
| Z-Score | 1.57 / 1.57 | 1.57 / 1.57 | **0（確定性）** |
| v4 門檻選擇 | 1.57 / 1.57 | 1.57 / 1.57 | **0（確定性）** |
| v1 | 4.33 / 7.33 | 6.33 / 9.33 | 2.2 倍 |
| v2 | 5.79 / 8.71 | 11.50 / 11.64 | 2.0 倍 |
| v3 | 13.07 / 4.71 | 4.64 / 4.79 | 2.8 倍 |

**兩條基準臂是逐位確定的**，雜訊全部在自由持倉那一側。
處置（寫在跑之前）：正式跑**每條自由持倉臂各執行 3 次**，
以三次的中位數作為該臂的點估計，並回報三次的全距。
v1 三次 = 約 10 天牆鐘；若時程不允許，退而只跑 1 次，
但**必須**在論文中把上表的執行間全距一併呈現，
不得讓單次結果看起來像是確定的。

**選這個視窗的唯一理由是它在 `split_half` 中點兩側剛好各 54 期**，
是所有同成本候選中唯一達到平衡的。其餘候選的偏斜如下（皆為 108 期、同成本）：

| 視窗 | 中點前／後 |
| :--- | :--- |
| 2007-07~2016-12 | 78 / 30 |
| 2008-07~2017-12 | 66 / 42 |
| 2009-01~2018-06 | 60 / 48 |
| **2009-07~2018-12** | **54 / 54** |
| 2010-01~2019-06 | 48 / 60 |

平衡是**在看到任何消融結果之前**、僅依日期算出來的，
與績效無關，因此不構成挑視窗。**視窗自此凍結，不因結果而更動。**

若改取 2006–2012（最便宜的早期視窗），108 期會全部落在

屆時無法回應「你的消融只在好年份成立」。

### 4.3 必須在論文中揭露的限制

1. **這是子期間（108 期），不是全期（295 期）。**
   子期間結果與全期並存於 `result.db`，兩者不可並列於同一張表。
2. **口徑是 `dollar`，主軸是 `signal`。** 本消融的五條臂彼此可比，

   這是「中點兩側平衡」與算力上限共同決定的結果，須照實說。

## 六、結果變數

### 6.1 主要

**每期每對進場次數**（換手率）。以 v4 為分母取比值。
理由：H1 講的是動作空間造成的**行為**差異，這是最直接的行為量。

### 6.2 次要

* 平均持倉天數
* 年化 Sharpe（H2）
* 零成本重算的 Sharpe 差距（H3，口徑限制見第二節）
* 出場狀態分解（正常收斂／停損／期末強平），沿用 `analysis/exit_status_decomp.py` 的三流口徑
* **五臂共同期數**（預期 108）。低於 100 即視為執行異常，須先查明再談結果。

### 6.3 明確不作為判準

終值、累積報酬、最大回撤。這些對單格 108 期太噪，且非本消融的主張。

## 七、統計程序

**觀測單位的相依性**：滾動步長 21 日、交易期 126 日 → 任一時點有 6 期並行，
期與期之間重疊。逐期視為獨立會構成偽重複（Hurlbert 1984），
與正文附錄採同一處置。

* **主要檢定**：逐期配對差分（v_i − v4，v_i − Z-Score），
  **循環區塊拔靴**，區塊長度 L = 6 期（一個完整重疊週期），10,000 次重抽。
  108 期 / L=6 → 18 個獨立區塊，是本設計統計檢力的實際上限，須在結果中明說。
* **多重比較**：主要族為 3 臂 × 2 基準 = 6 個比較，族內 BH-FDR 校正。
  次要結果變數各自成族，不與主要族混同。
* **報告內容**：每個比較都報點估計、拔靴 95% 區間、原始 p、BH 校正 p。
  不只報顯著與否。

## 八、事前判準

| 結論 | 條件 |
| :--- | :--- |
| **H1 成立** | 三條自由持倉臂中 **≥2 條**滿足「換手率比值 ≥ 2.0 **且** BH 校正 p < 0.05」 |
| **H1 不成立** | 上述條件未達成 |
| **H2 成立** | 三條自由持倉臂的 Sharpe **全部**不高於 v4 |
| **H3 成立** | 零成本重算下，自由持倉臂相對 v4 的 Sharpe 差距**縮小 ≥ 50%** |

門檻設在 **2.0 倍**而非 docstring 記載的 6 倍：這是**重跑取回**，
不是要求逐位重現。2.0 倍是寬鬆但非平庸的複製門檻——
明確聲明我們不要求同量級，只要求同方向且幅度非瑣碎。

**若 H1 不成立**：不改判準、不換視窗、不調參數重跑。

## 九、偏離與停止規則

* **崩潰**：同一 config 原樣重跑，不調任何參數。
* **牆鐘超時**：若超過 14 天仍未完成，**中止並記為「未能完成」**，
  不以降低 episodes 的方式搶時間。
* **偏離紀錄**：任何與前八節不符之處，一律追加於本節，不回頭修改前文。

### 啟動後、採信前必須逐項核對

`run_trading` 回報的 `SUCCESS` **不足以證明跑成功**——探針中 v1 對 27 期
「執行」7.4 秒、零筆有效模擬，仍回報 SUCCESS。故正式跑結束後須核對：

| # | 檢查 | 通過條件 |
| :-- | :--- | :--- |
| 1 | 各臂 log 的 `Error simulating pair` 次數 | **五臂皆為 0** |
| 2 | 各臂 log 的 `Skipping period` 次數 | 五臂**相同** |
| 3 | 五臂共同期數 | ≥ 100（預期 108） |
| 4 | 各臂單期耗時 | v1 約 **44.5** 分／期；**若遠低於此，即為未實際訓練** |
| 5 | `result.db` 的 `Hedge_Mode` | 五臂皆 `dollar` |
| 6 | db_method 尾綴 | **不含** `-PROBE`／`-SMOKE` |

任一項不過，視為執行失敗，修正後重跑，**不得就既有輸出做分析**。

## 十一、跑之前的先導觀察（**非確認性證據**）

下表來自成本探針的副產物：`ABLATION_EPISODES=5`／`10`、僅 14–15 個配對期
（v1 只有 3 個）、且**訓練預算遠低於正式的 150**。
放在這裡是為了留下記錄，**不作為 H1／H2 的證據**，正式結果只採第八節的判準。

| 臂 | 每期進場（四次執行） | 對 v4 倍數 | 平均持倉日 | Sharpe |
| :--- | :--- | ---: | :--- | :--- |
| Z-Score | 1.57 / 1.57 / 1.57 / 1.57 | 1.0× | 41.4 | +1.389 |
| v4 門檻選擇 | 1.57 / 1.57 / 1.57 / 1.57 | 1.0× | 16.2 | +1.390 |
| v1 LSTM-DQN | 4.33 / 7.33 / 6.33 / 9.33 | 2.8–5.9× | 3.5–14.6 | −1.88 ~ −2.46 |
| v2 修復版 | 5.79 / 8.71 / 11.50 / 11.64 | 3.7–7.4× | 1.2–9.9 | −1.31 ~ +0.14 |
| v3 FQI | 13.07 / 4.71 / 4.64 / 4.79 | 3.0–8.3× | 4.1–11.7 | −0.16 ~ +1.04 |

三點觀察：

1. **方向與 H1 一致**，且 v1 的 Sharpe（−1.88 ~ −2.46）落在
   `drl_threshold_trading.py` docstring 記載的 −1.1 ~ −2.3 範圍內
   ——那段失去明細的敘述，至少在方向與量級上重新量到了。
2. **效果大於雜訊。** 執行間全距約 2 倍，但最差的一次
   （v3 的 4.64 ÷ 1.57 = 2.95×）仍高於第八節寫定的 2.0 倍門檻；
   且兩條基準臂是逐位確定的，雜訊全在自由持倉一側。
3. **仍不能據此下結論。** 訓練預算只有正式的 1/30 ~ 1/15，
   「過度交易是不是訓練不足造成的」正好無法排除——這恰恰是第五節
   禁止下修 episodes 的原因。

> **時序聲明**：第八節的 2.0 倍門檻與全部判準，是在看到本節數字**之前**
> 寫定的。為了讓這件事可查核，本檔應在正式跑啟動前先 commit，
> 使「判準早於資料」有版本紀錄；本節之後再以修訂 commit 追加。
